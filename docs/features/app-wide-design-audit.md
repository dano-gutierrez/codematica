## One-Minute Brief

Apply [the design system](design-system.md) throughout the app. Reuse the existing controls and screen compositions, reduce redundant prose, and make the next action clear. Preserve source content, progress, grading, privacy, and the painted zombie campaign identity. This audit includes all routes and all supported platforms; completion of one shared component or the editorial page does not establish completion of the audit.

## Outcome / Contract

- Actions share geometry, spacing, semantic colors, accessible names, focus treatment, and touch targets. Touch actions carry visible labels; instructions never depend on hover.
- Page headings, gutters, form fields, filters, disclosures, error recovery, and completion states follow one documented pattern.
- Signed-in users can identify their account and sign out from navigation on both web and native. Admin links form a separate private section.
- Content reflows at 320 px, 200% browser text, native large text, and tablet Split View. Only code, diagrams, and intentionally horizontal carousels scroll sideways.
- Forms remain usable with the software keyboard. Menus and dialogs support keyboard and screen-reader dismissal and restore focus where appropriate.
- Anonymous browsing and local progress remain available without remote configuration. Auth and synchronization failures keep unsynced work and provide a concrete recovery.
- Campaign rails, maps, actors, painted colors, and world composition retain their existing identity. UX changes may simplify visible level labels without changing durable IDs or progress rules.

## Scope

### In Scope

All public, authenticated, admin, empty, loading, error, recovery, dirty, and completion surfaces below, including dynamic route variants and navigation between them.

### Out Of Scope

Replacing the game art direction, editing canonical learning content, changing scoring or persistence rules, adding paid services, and production deployment.

## Detailed Behavior

### UI / UX

Use [design-system.md](design-system.md) for component decisions and [adaptive-ui.md](adaptive-ui.md) for shell breakpoints. Keep explanatory detail in disclosures where users can find it; retain instructions needed to complete learning tasks. Consequential actions remain explicit and reviewable.

### Data Model And Persistence

Preserve existing content, local notebook ink, progress keys, review revisions, and database authorization. Do not use live accounts or publish posts for UI tests.

### Business Logic

Presentation changes must preserve route destinations, filter results, grading, progress writes, approval guards, and external request counts. Auth controls must reflect the current session and must not show successful operations when auth is unavailable.

### Failure And Edge Handling

Exercise unavailable configuration, rejected credentials, network rejection, signed-out transitions, stale asynchronous session checks, interrupted synchronization, empty search, exhausted practice, failed audio/clipboard/diagram rendering, and unsaved editorial revisions.

## Test Plan

- Unit/integration: begin behavior fixes with failing tests for accessible states, action payloads, auth lifecycle, error recovery, and keyboard/form behavior. Preserve meaningful existing coverage.
- E2E: explicit `@regression` journeys for changed behavior plus responsive route checks at 320, 390, 768, 1024, and 1440 px, 200% text, keyboard navigation, and axe checks. Run critical `@smoke` paths on Chromium and WebKit.
- Japanese and campaign route matrices give normal and enlarged text their own test cases. Both retain axe, overflow, geometry and capture checks; this avoids combining two expensive instrumented scans in one 30-second test. Public WebKit matrices use one worker per feature/width project to bound reuse; `--project='mobile-webkit*' --workers=1` runs the complete lane, and the editorial environment retains its three original projects. A static WebKit/axe/video diagnostic passes 24 independent contexts, so it does not establish the cause of the app-suite stalls.
- Native: Jest for shared component/adapter contracts; installed Android and iOS checks for safe areas, keyboard, large text, VoiceOver/TalkBack, menus, handwriting, and challenge navigation. Browser emulation is not device evidence.
- Live text: dispatch real dimension changes below the device layer, preserving Learn query/results, Markdown diagram state and map toolbar/position ownership through enlargement and restoration. Verify generated Android configuration/public runtime interfaces and actual installed text geometry; route/count-only checks do not establish readable glyphs. Retain exact artifact/source/capture identity and original device settings.
- Coverage: existing aggregate and per-file floors stay enforced; new reusable native modules are included in instrumentation.
- Source disclosure journeys must open the panel before querying visible links. Geometry checks read related bounds atomically so a layout change between asynchronous reads cannot produce a false overlap.
- Required gates: targeted TDD, `npm run test:coverage`, `npm run test:mobile:coverage`, `npm run lint`, `npm run typecheck`, `npm run mobile:doctor`, `npm run content:check`, `npm run build`, production artifact smoke, applicable Playwright and Maestro lanes.
