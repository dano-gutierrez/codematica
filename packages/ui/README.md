# @codematica/ui

Shared React Native-compatible Codematica UI.

Screens use React Native primitives, shared tokens, and platform adapters for navigation, progress, auth, links, and Mermaid rendering. Native uses them directly. Web uses platform-specific Next components; both implementations follow the shared design contract in `docs/features/design-system.md`.

Block code uses the fixed dark surface across Markdown, interviews, review, and diagram source. Fenced and indented Markdown reuse `CodeBlock`, including blocks nested in lists and quotes. Each block has a width-bounded horizontal scroll viewport, a stationary language label, and uncapped source height so the page scroll reaches every line. Inline snippets keep the readable prose chip and system font scaling remains enabled. `apps/mobile/src/__tests__/code-styles.test.tsx` guards styles, whitespace, nesting, and scroll props; `apps/mobile/e2e/code-layout.mjs` checks native geometry and gestures with agent-device. User-selectable themes are deferred. See the code-surface audit in `docs/features/markdown-knowledge-browser.md`.

Shared screens cover discovery, catalogs, Japanese Learn/Review/Dictionary/Resources, N5 flashcards and practice catalogs, dictionary details, embedded/path stroke practice, IME-backed open answers, approval-gated listening, interview collections, and read-only native web-exercise rubrics. Notebook handwriting uses native PencilKit on installed iOS and `react-native-svg` on Android; sentence answers use a real `TextInput` so iPadOS Scribble can recognize Pencil writing on-device. Japanese text exposes `ja-JP` accessibility language hints; font scaling remains enabled.

Learn discovery and resume cards omit description previews, retaining titles, labels and destinations at natural height. Their shared summary option defaults on for full-catalog/other resume compositions. Source summaries remain searchable. Learn's five section shortcuts omit the current page and wrap with system-text-scaled label space; its short search placeholder retains the complete accessible label. Header and sidebar home links have 48 dp minimum targets without scaling their artwork. See `docs/features/home-discovery.md` and the native screen regressions.

Native discovery card names include title, category/type and displayed difficulty; resume names include title and type. Editorial collection names include topic and review status with the title to help distinguish repeated titles. Explicit native accessibility labels override descendant aggregation, so keep these short visible labels in the name. Compact description hints stay absent; full-catalog summary hints are preserved.

Native Learn and Browse share `useSettledSearchQuery` inside `screens.tsx` to coalesce lookups after a 300 ms typing pause, with a polite pending state and hidden obsolete results. Timers cancel on input changes, clear and unmount. Browse also defers filter lookups while text is pending and suppresses its empty message until results settle. This reduces intermediate work on the JS thread; it does not create a worker or alter shared ranking/search fields. Component timing/cancellation tests complement default/large-text installed Maestro checks.

Shared `Button` owns visible scalable labels, semantic tones, 48 dp targets and busy/selected/disabled states. Shared screens reuse a labeled SearchField with a visible focus-restoring clear action. Use unframed sections for supporting readings/path units and named disclosures for optional diagram/editorial details. Failure and required-verification text stays visible. See the design-system new-page checklist before adding another control.

## Restore the Signal

`src/game/` provides NativeGameMap/NativeGamePlay, NativeGameBoard, NativeGameScene, and NativeDistrictArt. Skia and Reanimated are direct native runtime dependencies and UI peer dependencies. Editors and graph controls remain accessible native UI; CSS/SQLite use the bundled isolated local WebView. Native owns code text/caret during typing while change events update the session used by Run. Reset/scenario selection reseeds the editor and invalidates old text events. Jest instruments these files; Maestro must prove installed-app behavior.

`NativeGameScene` measures its own container and applies core miniature transforms to Skia, including paused/reduced-motion frames and success opacity. The shared atlas contains the editable chibi robot parts, enemies and ground shadows.

## Private editorial screen

`LinkedInAdminScreen` composes `AppScreen` and existing design tokens with the shared editorial store. NativeNavigation accepts an admin-membership flag for a separate Admin group and optional account identity/sign-out adapter for its footer and More menu. Database RLS and RPC guards enforce authorization. Native review supports manual creation, Unicode bold/italic/bullets/plain text, required analysis for manual drafts, edits, proposals, approval, rejection, withdrawal, sources and history. See `docs/features/linkedin-editorial.md`.

Editorial accessibility follows `docs/features/design-system.md`: 48 dp text actions, natural system font scaling, explicit discard before leaving dirty edits, and opt-in `AppScreen` keyboard-aware scrolling. Run native coverage and the disposable-data `.maestro/linkedin-admin.yaml` before native release; on-device screen-reader/keyboard validation is still required.

Japanese writing notebooks use 24 whole-prompt repetitions per sheet and support curated/custom text of 1–5 published characters. Ink and Easy/Balanced/Precise preferences stay on the device; coarse completion/unlocks optionally sync. Input detection is automatic with no mode buttons; one finger writes, two fingers scroll the paper, labeled screen-reader actions scroll the native viewport, and web wheel/trackpad scrolling stays available. `NotebookScrollContext` hands pan distance to the outer `AppScreen` at the paper bounds. Whole characters check automatically after a 400ms pen-up pause, including after correction, scrolling or difficulty changes; there is no manual submit control. The React-only notebook session delays rejected-character feedback by another 800ms, then shares the cancellable rejection timer (1.2-second correction window, 250ms fade). Native fades only temporary SVG/PencilKit ink and bounces the focused cell for 220ms while honoring Reduce Motion. Footer controls use content widths and a visibly labeled 48 dp restart action with an icon. Cells leave a clear gutter after the red margin. See `docs/features/japanese-writing-notebooks.md` for the implementation, persistence and validation contract.

Native notebook pages use a compact back/title row, inline examples and a reserved feedback area above the paper. Recall alone offers Show example. The paper ScrollView disables automatic touch scrolling, and its responder grant blocks native ancestor interception; two-finger and accessibility scrolling remain available. `AppScreen` accepts `keyboardShouldPersistTaps` so notebook creation works on the first tap with the keyboard open. Handwriting-route swipe-back protection lives in the mobile shell. Real layout/contact checks are in `apps/mobile/e2e/`.

Notebook catalog cards preview actual Japanese sheet prompts with optional romaji above them. `useNotebookRomaji` in the React-only notebook session module shares preference restoration and serialized writes between web/native; optional notebook storage methods keep this display setting on the device. Space for the annotations remains when they are hidden. See the notebook feature doc and catalog/native writing regressions.

The map and level routes pass focus ownership to `NativeGameMap` and `NativeGamePlay`. Covered native screens stop playback; level screens also stop their simulation timer and invalidate runner callbacks while preserving the shared attempt for explicit return/resume.

Map and challenge scenes also stop decorative playback outside their measured scroll viewport. Scene layout, scroll offset and viewport height determine visibility, including large-text reflow and keyboard resize; scrolling back resumes the existing art. The shared hook updates React only when visibility changes, preserving coarse map rendering during scrolling.

## Shared action controls

Reuse `src/Button.tsx` for native actions. It is extracted from the existing screen control and preserves primary/success defaults; new uses should specify tone and variant explicitly. Labels remain visible and scale with the system, actions are at least 48 dp, and busy/disabled/selected states are accessible. `AppScreen keyboardAware` gives forms handled keyboard taps, iOS padding avoidance and Android height avoidance. Game code uses the same platform behavior. Preserve input identity and draft through keyboard show/hide; relying only on Android window resize can leave an edge-to-edge editor covered. Login and practice forms adopt it. See `docs/features/design-system.md` and the full route/platform matrix in `docs/features/app-wide-design-audit.md`.

`Disclosure` in that module owns expandable supporting detail, a visible indicator, and the accessible expanded state. Interview rubrics and editorial details share it. Keep the current question and lesson actions outside disclosures. Recipe controls precede step explanations, and the solution language selector follows those controls before the full solution text.

`JapaneseReviewScreen` accepts an asynchronous `onRate` acknowledgment plus loading/error/reload state. It keeps the selected rating while saving or retrying and shows device-local success only after acknowledgment. The native route owns the stable save intent and serialized storage boundary; shared UI does not grade on retry.

`PracticeScreen` guided labs await the existing progress adapter, announce completion and offer Retry completion without discarding choices or private notes. Practice again resets transient work and requests a top-of-page scroll through `AppScreen`'s optional `scrollResetKey`; default screen scrolling and notebook ink ownership are unchanged. Notes are never sent to progress storage.

## Local search

`LocalSearch.tsx` owns the shared `useLocalSearch` hook and `LocalSearchFeedback`. Use it for native discovery/library queries instead of creating another debounce or WebView bridge. The fixed generated script enters through `CodematicaAdapters.searchScript`; it must never contain remote or user-authored JavaScript. The host owns metadata, request lifecycle, clearing, bounded startup/matching, renderer failure and retry. The hidden local runtime performs matching only. Without a script, the hook uses the same core functions synchronously. See the [native execution contract](../../docs/features/home-discovery.md#native-local-search-execution).

## Campaign map scenery

The map uses the shared fifty-position art manifest and statically imported contiguous textures in `assets/game/generated/map/`. `NativeDistrictArt` keeps terrain fixed and renders mist, amber motes and foliage at three bounded Reanimated depths. Measured panel positions drive culling and motion; reduced-motion changes reset all offsets. Future scenery has no playable controls and is omitted from the ascending level list.

## Live system text size

Use `src/AdaptiveText.tsx` for native text. It forwards the existing Text props, styles, refs, nested spans and accessible actions without disabling or limiting system scaling. Its native Text child changes identity only when `useWindowDimensions().fontScale` changes, so previously measured glyph boxes refresh while parent screens, controls, input values and progress remain mounted. Ordinary width or content changes preserve the text node. Text selection itself resets with the native text child.

`MarkdownReader` subscribes to dimension changes and reparses third-party text at the new font scale; sibling Mermaid previews and disclosure state stay mounted. The Android build hook publishes current dimensions without recreating the activity. Test both live enlargement and restoration with a populated form; source tests and cold large-text captures cannot prove the installed geometry. See `adaptive-text.test.tsx`, the design system and native deployment feature docs.

Shared `SearchField` binds its visible label to the input with a stable `useId`/`nativeID`/`accessibilityLabelledBy` association for Android, retaining `accessibilityLabel` on iOS. Keep the label identity through edits and clearing, and distinct across mounted copies; shortened placeholders are hints rather than the field name. The design-controls tests cover all four callers. See the design-system and home-discovery feature docs.
